The Industry Challenge

The Database Access & Performance Dilemma

❌ The Security & Risk Nightmare

  • • Non-technical teams lack SQL skills, while engineers spend hours writing ad-hoc queries.
  • • LLM-generated SQL often hallucinates, risks destructive writes (DROP, UPDATE), and bypasses safety checks.
  • • Accidental locks or table-locking writes can bring down production databases.

❌ The Performance Bottleneck

  • • Unindexed queries trigger costly Sequential Scans across hundreds of thousands of rows.
  • • PostgreSQL EXPLAIN plans are cryptic and intimidating for most software engineers.
  • • Database administrators are swamped triaging slow query tickets instead of scaling infrastructure.

Safety Architecture

5 Layers of Defense-in-Depth

1. AST Parsing & Validation

SQL is parsed into an abstract syntax tree via sqlglot. Only SELECT statements are permitted; DDL/DML is rejected immediately.

2. Schema Allowlisting

Queries are checked against an active table allowlist, preventing access to system catalogs or unapproved schemas.

3. Safety Limit Clamping

Queries missing a LIMIT clause are automatically clamped to 1,000 rows to prevent runaway memory usage.

4. Role-Level PostgreSQL Enforcement

Connected as readonly_user with default_transaction_read_only = on and a 5-second hard statement_timeout.

🛡️ Layer 5 Safeguard: Explicitly revokes EXECUTE on pg_sleep() to eliminate time-based blind SQL injection vectors.
